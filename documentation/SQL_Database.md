# Retail360 – SQL Database

## Database

Database Name: retail360

Database Technology: MySQL 8.0

## Purpose

MySQL is used as the database layer in the Retail360 pipeline.

The cleaned data generated by Python is loaded into MySQL raw tables before dbt performs the transformation and analytical modeling.

## Raw Tables

The Retail360 database contains the following raw tables:

- raw_customers
- raw_products
- raw_stores
- raw_sales
- raw_inventory
- raw_returns

## Raw Table Structure

### raw_customers

Stores customer profile information.

Columns:

- customer_id
- customer_name
- gender
- age
- city
- state
- region
- signup_date
- segment

### raw_products

Stores product information.

Columns:

- product_id
- product_name
- category
- subcategory
- brand
- cost_price
- selling_price

### raw_stores

Stores retail store information.

Columns:

- store_id
- store_name
- city
- state
- region
- store_type

### raw_sales

Stores sales transaction information.

Columns:

- order_id
- order_date
- customer_id
- product_id
- store_id
- quantity
- unit_price
- discount
- payment_method
- channel

### raw_inventory

Stores inventory observations.

Columns:

- inventory_date
- store_id
- product_id
- stock_quantity
- reorder_level

### raw_returns

Stores product return information.

Columns:

- return_id
- order_id
- product_id
- return_date
- return_quantity
- return_reason
- order_exists_in_sales
- return_quantity_exceeds_sold
- return_before_order

## Data Loading

The Python MySQL loader performs a full refresh of the raw tables.

Process:

1. Read processed files from the Data/processed folder.
2. Connect to MySQL.
3. Clear existing raw table data.
4. Load the processed datasets into MySQL.
5. Close the MySQL connection.

## Database Flow

Python Processed Data
        ↓
MySQL Raw Tables
        ↓
dbt Staging Models
        ↓
dbt Analytical Models
        ↓
Power BI

## Database Role

MySQL acts as the central database layer between Python data processing and dbt transformation.

Python handles ingestion and data quality preparation, while dbt handles transformation, testing, and analytical modeling.
